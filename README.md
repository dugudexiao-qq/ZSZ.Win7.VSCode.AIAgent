# ZSZ.Win7.VSCode.AIAgent

作者：dugudexiao。扩展 ID：dugudexiao.win7-ai-agent。版本 v1.10.0。MIT 许可。

源码：[https://gitcode.com/dugudexiao/zsz.Win7.AIAgent](https://gitcode.com/dugudexiao/zsz.Win7.AIAgent) · 问题反馈：[Issues](https://gitcode.com/dugudexiao/zsz.Win7.AIAgent/issues) 或邮件 dugudexiao@sina.com

一个让 Windows 7 SP1 上的 VS Code 1.70.2 也能用上本地大模型的 AI Agent 扩展。对接 OpenAI 兼容的 chat/completions 接口。扩展不内置模型名和服务地址，都由你自己填写。零依赖、离线安装。

模型跑在另一台新机器（或本机别处），插件只负责对话和工具执行。

## 一、它能做什么

| 能力 | 说明 |
|---|---|
| 本地大模型对话 | 侧边栏聊天，对接本地或内网模型服务；本地和内网站点免 API Key |
| Markdown 回答 | 回答按 Markdown 渲染，支持标题、列表、表格、代码块、引用、链接 |
| 长期要求 | 输入一句要求（如"注释用中文"）会永久记住，重启不丢 |
| 自动经验 | 工具报错后被修好时自动总结一条经验，下次直接照做；单独存储、可逐条删除 |
| 硬约束 | 只读、禁写、路径白名单、工具黑名单、Shell 开关，由代码强制拦截 |
| 写入文件 | 可切换可写模式，新建文件（自动建父目录）、改写、插入文本 |
| 完成自检 | 每轮回答下方核对这一轮真实做过什么：调了几次工具、成没成功、写入的文件在不在磁盘上；判为没动手时自动重试一次 |
| 上下文预算 | 历史按字符预算裁剪，工具结果保留头尾，小模型不会被几次大文件读取撑爆 |
| 运行命令 | 任意 PowerShell 和 CMD 命令，默认逐条弹窗确认，可关 |
| 子任务 | 复杂任务拆给子代理逐项执行，默认关闭，需要时再开 |
| 输入队列 | 上一条没回复完就继续输入，内容暂存，可编辑、撤回、调序 |
| 导入导出 | 导入 txt、md、csv、docx、xlsx；导出 md、csv、txt |
| 并排面板 | 聊天可开到编辑器区域，与文件夹左右并排 |
| 冲突自检 | 扫描重复副本和占用设置键的其他扩展 |

绿色"完成"只表示这一轮正常结束，不等于你要的改动真的发生。每轮回答下方还有一条完成自检，写明这一轮到底调了什么工具、成没成功、写过的文件在不在磁盘上；自检没通过时不会打绿色已完成。纯问答、以及全部成功的只读任务不显示这条自检。

## 二、安装

1. 把 zsz-win7-vscode-aiagent-1.8.1.vsix 拷到目标机器，命令行执行：

    code --install-extension zsz-win7-vscode-aiagent-1.8.1.vsix

2. 或在 VS Code 里按 Ctrl+Shift+P，输入 Extensions: Install from VSIX。
3. 装完执行 Developer: Reload Window（重新加载窗口）。

Win7 上务必在 settings.json 里设 "update.mode": "none"，防止 VS Code 被自动升到 1.71 以上后启动不了。

## 三、配置模型地址（首次必做）

扩展不内置任何地址和端口，必须自己填。端口写在地址里，格式为 http://主机:端口/v1。

方式一，命令面板（推荐）：Ctrl+Shift+P，输入 Set Server URL / Port，填完整地址，例如 http://192.168.1.20:8080/v1。填过一次完整地址后，以后只填端口号也能改；没填过地址时只填端口会被拒绝。

方式二，改配置文件：Ctrl+Shift+P，输入 Preferences: Open User Settings (JSON)，加入：

```json
{
  "update.mode": "none",
  "win7Agent.baseUrl": "http://192.168.1.20:8080/v1",
  "win7Agent.model": "你的模型别名"
}
```

Win7 上该文件在 C:\Users\用户名\AppData\Roaming\Code\User\settings.json。Ctrl+S 立即生效，不用重启。

模型别名要和模型服务那边暴露的名字完全一致，否则报 404。模型服务的端口：llama.cpp 常用 8080，Ollama 是 11434，LM Studio 是 1234。

## 四、日常使用

打开聊天：点活动栏的芯片 Z 图标，或命令面板执行 Open Chat。只看界面不需要模型服务、不需要联网。第一次建议先跑一次 Diagnose Connection 确认能连上。

顶部第一行是标题栏：左边 ZSZ AI Agent，中间是连接状态（点它跑诊断；没配 key 时点它直接填 key），右边是下拉菜单按钮（点菜单外或按 Esc 关闭）。标题栏下面一行是 4 个运行开关，文字直接写明当前状态，点一下切换（off 灰、on 高亮；窄面板会自动换行）：

| 开关 | 两个状态 | 作用 |
|---|---|---|
| 写入 | 只读 / 可写 | 是否允许 Agent 改文件 |
| 写入确认 | 开 / 关 | 关掉后写文件不再弹窗，直接生效 |
| 命令确认 | 开 / 关 | 关掉后 PowerShell、CMD、bat 不再弹窗，直接运行 |
| 子任务 | 开 / 关 | 开启后复杂任务拆给子代理，默认关 |

下拉菜单里是与上面开关无关的其它操作：

| 菜单项 | 作用 |
|---|---|
| 清空当前对话 | 只清当前会话（屏幕和模型上下文都清），其它对话不受影响 |
| 设置 API Key | 填或更换密钥；本地端点可留空 |
| 长期要求 | 管理记住的要求 |
| 经验记忆 | 查看/删除自动总结的经验，或整体关闭自动学习 |
| 在新面板打开 | 聊天开到编辑器区域，与文件夹并排 |
| 服务地址或端口 | 设置模型地址 |
| 插件设置 | 打开配置 |

底部一排按钮：Send、Stop、Import、Save，最右边是「切换对话 ▾」，点开向上弹出对话列表：顶部是「＋ 新对话」，下面每个对话一行（标题、最近时间，悬停出 × 可删除，删除不可恢复），当前对话有 ✓ 和高亮；点列表外或 Esc 收起。Import 导入文件进会话（支持多选，导入后文件显示在输入框上方，点 × 可撤回）；Save 把最后一次回答导出为 md、csv 或 txt，不是保存 Agent 生成的文件（那些由工具调用直接落盘）；＋ 新对话开一个新会话，旧对话留在下拉里随时切回。

状态栏用三种文字颜色区分：黄色表示等你确认，绿色表示这一轮完成，红色表示出错或取消。确认弹窗默认等 120 秒，没人点就自动取消那次操作、黄色消失，Agent 继续。关掉写入确认和命令确认后，对应动作不再弹窗，也不会出现黄色提示。

## 五、几个常用操作

和它对话：在输入框打字回车即可。它需要读文件或跑命令时，会以工具调用的形式执行；思考过程和每一次工具调用按发生顺序穿插显示在回复之间，默认折叠成一行（如「✎ 查看文件：src/agent.js · 0.8 s」，失败行直接写原因），点标题展开参数与结果，再点收起。

输入队列：上一条回复还没结束时可以继续输入并发送，内容会进入待发送队列。队列里每条都能编辑、撤回、上移、下移、全部撤回。当前回复正常结束后按队列顺序自动发送；本轮出错则暂停，显示"继续队列"。

子任务：菜单打开后，复杂任务拆给独立子代理，聊天区显示蓝色进度条目。一条消息最多 6 个子任务，最多嵌套 2 层。纯问答不用开。

让它写文件：默认是只读，点菜单把"写入模式"切成可写，Agent 就能新建、改写文件。是否每次弹窗由"写入确认"开关决定，关掉后直接写入。写入模式是总闸，只读时写不了。

看它改了什么：改动版本管理建议直接用 git 或 GitLens 等版本管理插件（内网离线包已包含 GitLens）。

怎么判断它真做了：每轮回答下方有一行自检结论，例如"有实际动作，已完成"或"声称已完成，但一步都没做"，后面列出这一轮的工具调用次数、每个工具成功几次失败几次、写入的文件是否真在磁盘上。它只看这一轮实际发生的动作，不看模型自己怎么说。这是经验判断，不是绝对证据，设 taskCheck 为 false 可关闭。

让它跑命令：默认每条命令弹窗显示完整命令由你放行。想免确认，把"命令确认"关掉。想彻底关掉命令功能，把 allowShell 设为 false。整目录复制这类活儿直接说"复制工作区所有文件到 backup"，它会用一条命令完成。

整目录复制、批量搬运这类活儿交给命令执行，不受工作区路径限制；文件读写工具只能碰工作区内路径。

## 六、配置项速查

所有键前缀是 win7Agent。Extension Settings 面板里每项标题和说明都是中文。

| 设置 | 默认 | 说明 |
|---|---|---|
| baseUrl / model | 空 / 空 | 服务地址与模型别名，必须自填 |
| timeoutMs | 1000000 | 请求超时，1000 秒 |
| confirmTimeoutMs | 120000 | 确认弹窗等待上限，超时自动取消那次操作 |
| stream / maxToolRounds | false / 20 | 打字机式逐字显示（本地回放，不影响工具执行）/ 工具轮数 |
| maxHistoryMessages / maxContextChars | 100 / 8000 | 历史条数上限 / 上下文总字符预算，按模型窗口调 |
| subtaskMode | false | 子任务模式，默认关 |
| constraints.readOnly | true | 禁止 Agent 写文件 |
| constraints.deniedTools | insertText | 工具黑名单 |
| constraints.allowShell / confirmShell | true / true | Shell 总开关 / 命令确认 |
| constraints.confirmWrite | true | 写入确认，关掉后写文件不弹窗 |
| constraints.allowedShellCommands | 空 | 命令白名单，按前缀匹配。空数组表示不限制；若只填了空串（如 [""]），则谁都不放行 |
| taskCheck | true | 完成自检开关，在回答下方核对这一轮的真实动作；判为没动手时会自动重试一次 |

## 七、排错

| 现象 | 处理 |
|---|---|
| 等很久没反应 | 看状态栏阶段和秒表；本地模型首次加载可能几分钟，1000 秒内可随时点 Stop |
| 弹窗被遮住或没人点，任务一直不动 | 确认弹窗默认等 120 秒后自动取消该次操作，Agent 继续；可用 confirmTimeoutMs 调整时长，或关掉对应确认开关 |
| Cannot reach the local model server | 确认模型服务已启动、地址和端口正确 |
| HTTP 404 | baseUrl 漏了 /v1，或 model 与服务端别名不一致 |
| Agent 不能写文件 | 默认只读，切成可写；再检查写入确认开关 |
| 写文件提示 Target directory does not exist | saveText 只改写已有文件，不会自己建目录。要新建文件（含多层目录）改用 createFile，或先把目录建好 |
| 读文件提示 File too large | readFile 上限 200 KB（204800 字节，含等于）。更大的文本用 importFile，上限 8 MB，会保留前 6 万字符 |
| 聊天区一直出现工具报错 | 这些是拦截提示，不是崩溃。同一个调用失败两次后第三次会被直接跳过；想让它别再试，补一句"用工作区内相对路径""要覆盖就加 overwrite:true" |
| PowerShell 报 UnauthorizedAccess，npm.ps1 加载不了 | 脚本被执行策略拦住。插件已用 -ExecutionPolicy Bypass 启动子进程（只影响该进程，不改注册表）；仍失败说明域组策略强制了 Restricted，改用 shell: "cmd" |
| 关了确认还弹窗 | 若弹的是写入确认或工具审批，它们是独立开关；跑 Diagnose Connection 看各级设置取值 |
| 装了另一个 AI Agent 怕冲突 | 跑 Diagnose Connection，看输出里的冲突扫描结果 |
| 设置改了不生效 | 多半装了多个版本，先卸载再重装 |
| 升级后界面还是旧样子（工具调用还是大段原文、思考挤在底部一大块） | VS Code 还在运行升级前加载的旧扩展代码：把所有 VS Code 窗口全部关闭再重新打开（只重开聊天面板或 Ctrl+R 不够）。v1.9.1 起脚本带构建时间戳，正常升级后重载窗口即可生效 |
| 回答下面写"声称已完成，但一步都没做" | 这一轮模型没调任何工具，只是嘴上说做完了。它会自动重试一次（界面上会显示系统提示），仍失败就再发一次或加一句"先调用工具再回答"；同时确认写入模式不是只读 |
| 设置界面显示 No settings found | 清空搜索框，输入 @ext:dugudexiao.win7-ai-agent；仍不行就改 settings.json，功能一样 |
| 想同时看文件夹和聊天 | 点菜单"在新面板打开" |

### 使用技巧

- 直接说目标，不必替它规划步骤："把工作区所有文件复制到 backup"。
- 绿色"完成"只代表本轮结束；是否做成，看回答下方的自检行。
- 自检显示"一步都没做"：重发一次，或补一句"先调用工具再回答"。
- 回复未结束可继续输入，进队列，可编辑、撤回、调序。
- 默认只读，写文件前在菜单切换为可写。写入确认控制写文件是否弹窗。
- 命令默认逐条弹窗；关闭命令确认后不再弹。
- 弹窗无人处理时，默认 120 秒取消该次操作，任务继续。
- 只看界面：不用填地址、不用 Key、不用联网，先跑一次 Diagnose Connection。

### 配置方法

- 地址：win7Agent.baseUrl，格式 http://主机:端口/v1；模型名：win7Agent.model，需与服务端别名一致。
- 命令面板 Set Server URL / Port 可填地址；首次必须填完整地址，只填端口会被拒绝。
- 也可改 settings.json（Win7：C:\Users\用户名\AppData\Roaming\Code\User\settings.json），保存即生效。
- 三个常用开关在下拉菜单：写入模式、写入确认、命令确认。
- 弹窗等待上限：confirmTimeoutMs，默认 120000 毫秒，命令确认、写入确认、工具审批共用。
- 完成自检：taskCheck，只提示不阻断，纯问答与全部成功的只读任务不显示。
- 上下文预算：maxContextChars，默认 8000 字符；中文约 1 字符 1 token，8k 模型保持默认，16k 以上可调到 14000。
- 打字机显示：stream，本地分片回放，不影响工具执行。
- Win7 建议加 "update.mode": "none"，避免自动升级后无法启动。

- v1.7.3：模板彻底写坏时的最后防线——invoke 开标签整个丢失、只剩参数标签和孤立闭合标签（连工具名都拿不到）时，不再把模板原文当回答显示；改为自动向模型回填一条格式纠错（最多两次），要求改用一行 JSON 重发；重试上限后只显示剥掉模板碎片的正文。提示词同步强调「只用一行 JSON，不要输出 DSML/标签模板」。
- v1.7.4：空参数浪费轮次的治理——①解析兜底：只解析出一个调用且 args 为空时，若正文里另有一个参数键全部认识的 JSON，自动捞回当 args 直接执行（省一整轮重试）；②捞不回时「requires args.xxx」报错附带完整重发示例，模型照抄即可，一次重试必成功；③提示词加「发出调用前自查 args 必填参数」。
- v1.7.5：修复 @ 文件引用失效——宿主回包时弹层仍处于隐藏态被跳过重绘，导致首次打 @ 毫无反应（必须再敲一个字符才出现）；现在一来就有「正在读取工作区文件…」占位，回包后立即重绘，读不到文件会显示原因。触发边界放宽为「@ 前不是字母/数字/路径字符」，中文后与全角 ＠ 都能触发，邮箱里的 @ 不触发；中文输入法补 compositionend 触发。另加「不要编造执行记录」守则：本轮没有任何真实工具执行、回复里却出现 TOOL RESULT / STATUS: OK 样式文字时，明确提示文件并未改动。
- v1.7.6：堵住第 4 种调用模板泄漏——DeepSeek 特殊 token 残片（<｜tool…，全角 ｜）混进正文并把调用 JSON 的开括号一起吞掉（<｜tool":"runCommand",…}}），v1.7.5 既解析不出也检测不到，整段原文漏进聊天区。现在：残缺形态自动修回 {"tool 并照常解析执行；完整特殊 token（<｜tool▁call▁begin｜> 等）剥掉后照常解析；修不回来的残片判为坏模板自动要求重发，原文不显示。半角 <|x|>（正则/管道常见写法）不误判。
- v1.7.7：超长写入报错带指引——单次写入上限 20000 字符，此前报错只有一句「Text too long to write」，小模型第一把写几万字被拒后只会原样重试，白费一轮。现在报错带实际字符数、上限和拆分方案（拆成多个小文件逐个 createFile）；系统提示词同步加「写大文件先按模块拆分，别先试超长再等报错」。
- v1.7.8：尾逗号容忍——模型收尾时输出的调用 JSON 带尾逗号（如 {"command":"...",}}），JSON.parse 失败、坏模板检测也不认（形态太接近合法 JSON），原文漏进聊天区且命令没跑。现在解析前逐字符剥离「字符串之外、紧跟 } 或 ] 的逗号」；字符串内部的 ,} 是数据不受影响；DSML 参数体与 args 双重编码路径同样兜住。日志原文回归：Get-ChildItem 调用可直接执行。
- v1.7.9：①Qwen 模板第 7 种退化检测——function 开标签与 parameter 标签整体丢失、只剩参数值和孤立 </function> 时（真机截图），判坏模板自动要求重发，原文不显示，显示层剥标签行；②粘贴兜底——paste 事件手动在光标处插入纯文本，Ctrl+V 被宿主吞掉时 50ms 后主动读系统剪贴板补插（不会重复插入）；③拖文件到聊天区自动变成 @相对路径 引用——webview 拦截 drop 交给宿主，工作区内绝对路径直接转相对，工作区外按文件名在清单里模糊匹配，悬停时输入框显示虚线提示。
- v1.8.0：①自动经验记忆——工具报错之后又被修好时，把解决方式自动记成一条长期经验（如「createFile 遇到文件已存在 → 加 overwrite:true」），下一次请求起注入系统提示词，越用越少犯同样的错。只记「已解决」的错（只报错没修好不记），单独存储、单独计数（最多 12 条），不占用你手写的「长期要求」；聊天区会明确提示「已写进长期记忆：…」，菜单「经验记忆」里可逐条查看/删除，设置 win7Agent.autoLearn 可整体关闭。②导入的文件出现在输入框上方——导入后输入框正上方出现文件标签（文件名 + 类型 + 字符数，截断有标记），点 × 就把这份文件从对话里撤掉（下一轮模型真的看不到它了）；支持一次导入多个文件。
- v1.8.1：界面文案整改——①去掉 emoji：聊天区原有 4 个依赖彩色 emoji 字体的符号（经验记忆提示 U+1F9E0、附件标签 U+1F4C4、导入提示 U+1F4CE、等待确认 U+23F8），Windows 7 既没有 Segoe UI Emoji，也缺这些字形，真机上显示为方块；现改为纯文本前缀与纯文件名，消息类型仍靠边框和颜色区分，只保留 ▸ ▾ ✓ ⚠ ↳ 这类 Win7 字体覆盖的几何符号。②附件引用只显示文件名：输入框上方的文件标签不再把 docs/… 这类目录挤进 chip（长路径被省略号截掉，反而看不出是哪个文件），完整相对路径留在悬停提示里。
