# ZSZ.Win7.VSCode.AIAgent

[![Version](https://img.shields.io/badge/version-1.13.2-blue)](https://github.com/dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent) [![License: MIT](https://img.shields.io/badge/license-MIT-green)](./LICENSE) ![Platform](https://img.shields.io/badge/platform-Windows%207%20SP1%20%2B%20VS%20Code%201.70.2-lightgrey)

让 **Windows 7 SP1 + VS Code 1.70.2** 这类无法升级的老机器也能用上 AI Agent 的扩展。对接任意 **OpenAI 兼容的 chat/completions 接口**（本地 llama.cpp / Ollama / LM Studio，或内网模型服务），模型跑在别处，插件负责对话、工具执行与安全约束。

- 扩展 ID：`dugudexiao.win7-ai-agent` · 作者：dugudexiao
- 源码：[github.com/dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent](https://github.com/dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent)（镜像：[GitCode](https://gitcode.com/dugudexiao/zsz.Win7.AIAgent)）
- 反馈：[GitHub Issues](https://github.com/dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent/issues) 或 [dugudexiao@sina.com](mailto:dugudexiao@sina.com)
- 零依赖（CommonJS，无 npm 包），离线 VSIX 安装，MIT 开源

## 核心特性

**Agent 能力**

- 侧边栏聊天，Markdown 渲染；思考过程与工具调用按发生顺序穿插显示，默认折叠一行
- 工具集：读/写/建文件、插入编辑器、列目录、导入导出、本机命令、子任务委派
- 子任务模式：复杂任务拆给独立子代理逐项执行（最多 6 个/轮、2 层嵌套，默认关闭）
- @ 引用工作区文件：清单由扩展自己遍历（首次打开也完整，不受 `files.exclude` 影响），拖拽/粘贴自动转为引用

**记忆与上下文**

- 长期要求：一句话永久生效（如「注释用中文」），存 globalState
- 自动经验：工具报错被修好后自动总结成经验并注入后续提示词，可逐条删除
- **记忆容量条**：对话顶端常驻一条进度条，随时告诉你「AI 还能记住多少前文」——**回复过程中实时增长**（工具结果、正在生成的正文都算），占用到 80% 变黄，开始丢弃旧消息时变红并写明「更早的 N 条已不再参与」；改预算或换模型时，若与模型窗口明显不匹配会提醒一次，可直接点「设为推荐值」
- 自动上下文压缩：历史超限时旧对话自动摘要成一条，长任务不再「忘记」开头（压缩后进度条会当场回落）
- 多模型配置（profiles）：多套「地址 + 模型 + Key」命名保存，菜单一键切换
- 工作区文件清单随提示词提供；支持项目根目录 **AGENTS.md** 注入

**安全与控制**

- 代码级硬约束：只读模式、路径白名单、工具黑名单、命令白名单、Shell 总开关
- 写入确认 / 命令确认逐条弹窗（可关），弹窗超时自动取消，任务不挂死
- 每轮写入前自动快照，回复下方可「↩ 撤回本轮改动」（保留最近 5 轮）
- 完成自检：按真实工具调用判定本轮是否真做了事，判为没动手时自动重试

**Windows 7 适配**

- runCommand 支持 **PowerShell 5.1 / CMD / Git Bash** 三种 shell，默认自动选优
- 系统提示词按当前 shell 注入语法规则；命令失败自动识别「shell 语法错配」并给出纠正提示
- PowerShell 子进程自带 UTF-8 输出、TLS 1.2、进度静音、`-ExecutionPolicy Bypass`
- 输出上限 + 双超时（墙钟/空闲）+ 进程树强杀，命令不会挂死扩展

## 安装

**方式一（推荐）：从 GitHub Releases 下载安装包**

每个版本都有对应的 Release（发行版），附件即离线安装包：

1. 打开 [Releases 页](https://github.com/dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent/releases)，下载 **v1.13.2** 的附件 `zsz-win7-vscode-aiagent-1.13.2.vsix`（约 200 KB）
   （直链：[Releases/download/v1.13.2](https://github.com/dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent/releases/download/v1.13.2/zsz-win7-vscode-aiagent-1.13.2.vsix)）
2. 安装：`code --install-extension zsz-win7-vscode-aiagent-1.13.2.vsix`（或在 VS Code 中 `Extensions: Install from VSIX`）
3. 重载窗口：`Developer: Reload Window`

> 国内访问 GitHub 不稳定时，可用 [GitCode 镜像](https://gitcode.com/dugudexiao/zsz.Win7.AIAgent)：[发行版页](https://gitcode.com/dugudexiao/zsz.Win7.AIAgent/releases) 与 GitHub 逐版对应（每个版本都带 `.vsix` 附件），也可以在文件页的 `dist/` 里下最新一版。

**方式二：从源码打包**

克隆仓库后在项目根目录执行 `vsce package`（或已有的打包脚本）生成 VSIX，再按上述方式安装。

> Win7 务必在 settings.json 中设置 `"update.mode": "none"`，防止 VS Code 被自动升级后无法启动。

## 快速开始

1. **配置模型地址**：`Ctrl+Shift+P` → `Set Server URL / Port`，填 `http://主机:端口/v1`（llama.cpp 常用 8080，Ollama 11434，LM Studio 1234）；模型名需与服务端别名完全一致
2. **（可选）填 API Key**：本地/内网站点可留空；面板菜单 → 设置 API Key
3. **诊断连接**：命令面板 → `Diagnose Connection`，确认能连通
4. 打开聊天：活动栏芯片图标，或命令面板 `Open Chat`

## 使用要点

- **最小化**：点标题栏右侧 `−` 收起整个侧栏，不停止当前任务；VS Code 底部状态栏会显示「Agent 运行中 / 已结束」，点一下恢复。编辑器里的聊天标签也可最小化，后台运行中恢复时会一并还原历史和已生成内容
- **记忆容量条**（标题栏与对话之间）：`记忆 43% · 12 万 / 28 万`，回复中会显示「生成中」并实时走字；悬停可看字符数、消息条数、本轮实际送入几条、被丢掉的条数，以及是哪项设置决定上限
- **上下文预算提醒**（只在改设置时出现，不占界面）：改 `maxContextChars` / `maxHistoryMessages` 或换模型时，按 `model` 推断窗口并比对（8k≈6000 字符、32k≈2.3 万、128k≈9 万，上限 20 万）；偏离 20% 以上才弹一句，点「设为推荐值」会把字符数与条数一起写好。同一组「模型 + 当前值」只提醒一次，选「保留当前」后不再啰嗦，模型名认不出来则完全不提
- **4 个运行开关**（标题栏下方）：写入（只读/可写）、写入确认、命令确认、子任务
- **下拉菜单**：清空对话、API Key、长期要求（点开后在输入框里直接写，回车即记住）、经验记忆、模型配置、新面板打开、服务地址
- **多会话**：底部「切换对话 ▾」新建/切换/删除对话，各自独立上下文
- **输入队列**：回复未结束可继续输入，队列可编辑、撤回、调序；一轮结束（成功或超时）就自动发下一条，**不再等人点「继续队列」**；只有连续 2 次超时、认证失败、手动 Stop 才暂停
- **定时任务**：把任务写好，点发送键旁的「定时」，选 30 分钟后 / 凌晨 02:00 / 自定义时刻，可只跑一次或每天同一时间；到点自动发起一整轮，正在回复时会排队等这一轮结束；夜里无人值守时确认弹窗按推荐自动执行
- **版本更新提醒**：启动后一天查一次新版本，有更新时弹一条带「查看更新 / 跳过此版本」的提示；更新源可自定义（官方 GitHub、别人的仓库、内网自建 feed 都行），断网/内网不通只写日志，不打扰你
- **过程展示**：工具调用默认折叠一行（如 `✎ 查看文件：src/agent.js · 0.8 s`），失败行直接写中文原因，点标题展开详情
- **绿色「已完成」≠ 事情真做成了**：以回答下方的自检行为准

## 定时任务（错峰跑批）

内网算力白天紧、夜里松，可以把整块的活排到没人用的时段：

1. 在输入框里写好任务（一句完整的话，例如「把 `docs/` 下所有 markdown 的外链检查一遍，汇总失效的」）
2. 点发送键旁的 **定时**（`Send` / `Stop` 右边）
3. 选时间：30 分钟后 / 1 小时后 / 2 小时后 / **凌晨 02:00（错峰）** / 指定时刻（`HH:MM`）
4. 选重复方式：**每天这个时间**（夜里跑批的常规用法）或**只跑这一次**
5. 到点后 Agent 自己发起一整轮，对话里那条消息带 `定时 02:00` 角标，一眼能看出不是自己打的字

管理：面板顶端（记忆条下方）会常驻一条**定时任务清单**，折叠成一行显示「定时任务 N · 最近一条的下次执行时间」，点开逐条看时间、倒计时、每天/仅一次、暂停状态，点某条直达该任务的「立即执行 / 暂停 / 删除」。新建/删除/暂停/到点后清单自动刷新，没有任务时整条隐藏。

也可以用 `Ctrl+Shift+P` → `定时任务：管理` 打开同样的操作菜单。

三条要知道的限制与约定：

- **VS Code 必须开着**。定时器活在扩展宿主进程里，关掉 VS Code 到点不会执行。错过的任务直接跳过（一次性任务失效；每天任务排到第二天），不会在你中午开机时补跑凌晨两点的批。
- **无人值守：确认弹窗不弹，改按推荐执行**。夜里没人点弹窗，老做法是等 `confirmTimeoutMs`（默认 120 秒）超时后当拒绝，整条任务白跑。现在定时任务那一轮里，写入确认、命令确认、工具审批三个弹窗都按推荐选项（= 弹窗上的主按钮）自动通过，并在对话里留一条 `[无人值守] 定时任务未弹窗询问，已按推荐自动确认：…`，事后能看清 AI 替你点了什么。想恢复逐次确认：设置里关掉 `win7Agent.scheduledUnattended`。注意这**不会**绕过只读模式——`constraints.readOnly` 仍然拦住所有写入。
- **任务最多 20 条**，随窗口生命周期存活；存在 globalState 里，重载/重启不丢。

## 版本更新提醒

扩展本身不带自动升级（VSIX 是离线安装的），所以它只做「提醒」：查到新版本后弹一条提示，点「查看更新」打开下载页，点「跳过此版本」就不再念这一个版本。

**更新源可以改**。设置里把 `win7Agent.updateRepo` 填成下面任意一种：

| 写法 | 例子 | 走哪里 |
|---|---|---|
| `owner/repo` | `dugudexiao-qq/ZSZ.Win7.VSCode.AIAgent`（默认） | GitHub Releases API |
| GitHub 仓库主页 | `https://github.com/你的镜像/agent` | 自动转成 API 查询 |
| 自定义 feed | `https://内网/aiagent/latest.json` | 直接 GET 这个 JSON |

feed 的内容很宽松，认这三种形态之一即可：

```json
{ "version": "1.12.3", "url": "https://内网/aiagent/x.vsix", "notes": "改了什么" }
{ "tag_name": "v1.12.3", "html_url": "https://内网/aiagent/releases", "body": "改了什么" }
{ "releases": [ { "version": "1.12.2" }, { "version": "1.12.3" } ] }
```

几条行为约定：

- **一天最多查一次**（`checkUpdatesOnStartup` 关掉后完全不自动查），手动命令不受限制；改 `updateRepo` 会清掉这个节流，下次激活立刻生效。
- **查不到不打扰**：断网、代理拦截、feed 写错都只写输出面板日志；只有你手动点「检查更新」时才会把失败原因弹出来。
- **「检查更新」在命令面板**（`ZSZ.Win7.VSCode.AIAgent: 检查更新`），不受「跳过此版本」影响，随时能强制查一次。
- 只认 `http/https` 链接；feed 返回 404 时会提示「仓库或 feed 地址不对，或还没有发布任何版本」。
- 版本比较按数字段（`1.12.10 > 1.12.9`），`v` 前缀自动忽略，正式版大于同号预发布版。

## 配置速查

所有设置项前缀 `win7Agent`，设置界面有中文说明。

| 设置 | 默认 | 说明 |
|---|---|---|
| `baseUrl` / `model` | 空 | 服务地址（`http://主机:端口/v1`）与模型别名，必填 |
| `preferShell` | auto | 默认 Shell：auto=有 Git Bash 用 bash，否则 PowerShell |
| `constraints.readOnly` | true | 只读模式（写入工具被拦截） |
| `constraints.confirmWrite` / `confirmShell` | true | 写入 / 命令逐条确认 |
| `constraints.allowShell` / `allowedShellCommands` | true / 空 | Shell 总开关 / 命令白名单（按 `;` `&&` `\|` 分段，每段都要命中） |
| `constraints.deniedTools` | insertText | 工具黑名单 |
| `maxHistoryMessages` / `maxContextChars` | 100 / 8000 | 历史条数 / 上下文字符预算；改这两项时会按当前模型给一次推荐值（可选一键套用） |
| `maxToolRounds` / `timeoutMs` | 20 / 1000000 | 工具轮数 / 请求超时 |
| `subtaskMode` / `taskCheck` | false / true | 子任务模式 / 完成自检 |
| `stream` / `confirmTimeoutMs` | false / 120000 | 打字机显示（本地回放）/ 确认弹窗超时 |
| `scheduledUnattended` | true | 定时任务无人值守：确认弹窗改按推荐自动执行 |
| `sessions` / `autoLearn` | - / true | 会话保留配置 / 自动经验学习 |
| `updateRepo` | 官方仓库 | 版本更新源：`owner/repo` 或返回 JSON 的 https 地址（留空=不检查） |
| `checkUpdatesOnStartup` | true | 启动后自动查新版本（一天最多一次，失败静默） |

## 排错速查

| 现象 | 处理 |
|---|---|
| 连不上模型 | 确认服务已启动；先跑 `Diagnose Connection` |
| HTTP 404 | baseUrl 漏了 `/v1`，或模型名与服务端别名不一致 |
| 不能写文件 | 默认只读：菜单切「写入：可写」，再检查写入确认开关 |
| 写文件报 Target directory does not exist | saveText 不建目录；新建文件（含多层目录）用 createFile |
| 读文件报 File too large | readFile 上限 200 KB；更大文本用 importFile（8 MB） |
| npm.ps1 报 UnauthorizedAccess | 扩展已用 `-ExecutionPolicy Bypass` 启动子进程；仍失败说明域组策略强制 Restricted，改用 `shell:"cmd"` |
| 升级后界面没变化 | 所有 VS Code 窗口完全关闭再启动（仅重载窗口不够） |
| 命令报「疑似 shell 语法错配」 | 按报错里 HINT 的提示换对应 shell 语法重发即可 |

- **v1.13.0**：上下文预算**按模型推荐**。`maxContextChars` 以前是个裸数字，默认 8000 对 128k 的云端模型太保守（只能记住最近几轮），对 8k 的本地小模型又偏大。现在按 `model` 的族系推断窗口（DeepSeek/GLM/Kimi 128k、Qwen 本地 32k、Qwen-max 128k、Llama 3.x 128k、Claude 200k、Phi 4k…），按窗口的 70% 折算字符预算（其余留给系统提示、工具结果和回复），折算后同步给出历史条数。**提醒只发生在改设置时**：动 `maxContextChars` / `maxHistoryMessages` 或换模型，且与推荐值差 20% 以上，才弹一次「设为推荐值 / 保留当前」，点前一个会把字符数与条数一起写好；同一组「模型 + 当前值」只提醒一次，关掉弹窗也记住，模型名认不出来就完全不提——宁可让人自己填，也不编一个值把请求撑爆。 提醒另有 1.2 秒防抖：设置界面的数字框每敲一位就保存一次，不防抖的话填个 23000 会被连弹好几次；连敲合并成最后一次，且同一时间只允许一个提醒在飞。  
同版补了**子任务等待的可见性**：主 Agent 是「请求 → 本地执行工具 → 再请求」的循环，子任务就是其中一个工具，所以子任务运行期间主任务本来就没有请求在飞——这不是中断。但状态栏原先只停在「正在执行工具 runSubtask…」，几分钟不动很容易被当成卡死。现在子任务开始时写明「主任务等待其结果（等待期间主任务不发送请求，属正常）」，子任务每推进一步状态栏同步「主任务等待中 · 子任务 N：…」，返回时提示「结果回填主任务，继续推理」。smoke 里按请求顺序做了回归：主请求 → 子请求 → 主请求（带 SUBTASK RESULT），子任务上下文不含主历史，全程 busy 不中断。  
同版做了一轮**界面打磨**（只动样式与可读性，不动交互逻辑）：输入框改为圆角 + 聚焦细光环，按钮统一 120ms 过渡、键盘 `:focus-visible` 焦点环与「只亮边框不变实心蓝」的 hover，记忆条改成细渐变（黄色/红色警示仍盖得住），滚动条收成 10px 细条，代码块圆角统一，空对话显示一张虚线引导卡片（说明 @ 引用与 Ctrl+Enter），并支持系统「减少动态效果」（关掉状态点呼吸与进度条滑动），记忆条补 `aria-valuetext` 让读屏能报出「用了多少 / 上限多少」。全部沿用主题变量，未使用 `backdrop-filter` / `:has()` 等 Win7 老 Electron 不支持的特性。
- **v1.12.8**：记忆条改成**真正实时**。原来只在一轮开始与结束时各刷一次，回复过程中一直不动——因为工具结果和流式正文都在临时上下文里，还没写进会话历史。现在 agent 每轮把「本轮额外占用」（工具结果、重试提示等）报给面板，前端按 delta 累计正在生成的正文，250ms 节流刷新，条会随着这一轮变长；文字加「生成中」，悬停说明其中多少字符尚未落库。失败或结束时清零，回到真实占用。
- **v1.12.7**：新增**记忆容量条**。对话顶端常驻一条细进度条，显示当前会话的上下文占用（字符数 / 预算 + 百分比），悬停可看消息条数、本轮实际送入几条、被丢弃几条。占用 80% 变黄，开始丢旧消息或到 100% 变红并写明「更早的 N 条已不再参与」，自动压缩生效后会当场回落——不用等 AI 答非所问才发现它把开头忘了。容量按 `maxContextChars` / `maxHistoryMessages` 计算，与实际送入模型的裁剪逻辑同源。
- **v1.12.6**：修「模型把工具调用当成正文打印出来」。DeepSeek V3.2 把调用分隔符换成了 `｜｟DSML｠｜`（全角竖线 + U+FF5F/FF60），旧解析只认 `｜｜DSML｜｜`，整段 `<invoke name="readFile">…` 认不出来，就被当成最终回答显示给用户，任务还标了「已完成」。现在先把 `｟｠` 折成竖线再按老形态归一，正常调用直接执行；只剩外层标签、拿不到工具名的畸形输出也会被判为坏模板并要求模型重发，不再漏进聊天区。
- **v1.12.5**：三处交互修正。① **「定时」从菜单搬到发送按钮旁**，输入框上方写好任务、点一下就能排时间，不用先翻「···」菜单；② **发送按钮不再改名**：正在回复时它原来会变成「排队」，看着像另一个功能，现在始终是 `Send`，悬停才提示「点击会排到这一轮结束之后发送」；③ **修「关掉 VS Code 再打开，刚才的对话不见了」**：面板刚挂载时那份历史重放常常赶在页面脚本注册监听之前，就此丢掉，之后没有任何补发——现在 webview 报 `ready` 后会再定向重放一次（正在跑的那一轮除外，免得清掉流式输出）。
- **v1.12.4**：修「模型换了，界面还写着旧名字」。徽章上的模型名以前只在面板打开和每轮结束时推一次：用户在设置里把 `llama.cpp` 换成别的模型，请求其实已经走新配置，界面却一直挂着旧名字——现在任何 `win7Agent` 设置变更都会立刻重推状态。另外，如果用户设置和工作区 `settings.json` 里都写了 `model`，生效的只有优先级高的那份，徽章显示的就是它；悬停会补一句「当前生效：工作区设置；用户设置「llama.cpp」未生效」，不用再靠猜。
- **v1.12.3**：新增**版本更新提醒**。启动后一天查一次新版本，有更新时弹「查看更新 / 跳过此版本」，跳过的版本不再打扰；命令面板「检查更新」可随时手动查。**更新源可自定义**：`win7Agent.updateRepo` 支持 `owner/repo`（GitHub Releases）、GitHub 仓库主页链接，或任何返回 JSON 的 https 地址（内网镜像自建 feed）；断网/内网不通只写日志，手动查才报错。顺带把白名单说明改成「按命令分段匹配」，`maxToolRounds=0` 真正禁用工具。
- **v1.12.2**：一次全量代码审计（漏洞 + 冗余）。修的真实缺陷：① **命令白名单只比前缀**——`allowedShellCommands: ["git"]` 时 `git status; del /s /q C://*` 也被放行，现在按 `;` `&&` `||` `|` 换行切开，每段都要命中白名单且前缀后必须是命令边界（`dirx` 不再冒充 `dir`）。② **连点发送启动两轮**：`_busy` 原来在两个 `await` 之后才置位，面板和边栏同时发（或手快连点）会有两轮 runAgent 并行、共用同一个取消令牌，现在先占位再 await。③ 正在回复时「清空对话」会把这一轮的回复写回空白会话，现在与切换/删除一致，先提示再拒绝。④ `maxToolRounds: 0` 文档写「完全禁用工具」，实际被 `|| 20` 吃成 20，现在真的禁用。⑤ 索引/解析两处卡死风险：`{` 泛滥的模型输出让括号扫描退化成 O(n²)（已加扫描预算），命令输出跨 chunk 的中文被切成乱码（改用 StringDecoder）。⑥ 小修：文件正文里写着 `STATUS: FAILED` 不再被当成本轮命令失败；`deniedTools` 大小写不敏感；撤回快照的路径校验从字符串前缀改为 `path.relative`（`app-evil` 不再被当成 `app`）；settings.json 带 BOM 时设置体检不再「假干净」；`stripJsonc` 不再改动字符串里的 `, }`；只输入 6 位数字不再被当成主机名；会话持久化从「只留 40 条」放宽到 200 条 / 40 万字符，长任务重开窗口不再丢任务前提。清理：删掉开发期残留的 23 张 `scripts/_preview` 截图、两个一次性图标脚本、`ui-preview.html`、`icon-preview.png` 和 4 个未使用的图标变体；仓库里只保留最新一版 `dist/` 安装包（旧版走 Releases）。
- **v1.12.1**：修两个「队列停住」和「定时任务白跑」的问题。① 队列的「已暂停」状态会一直粘着：某次 401 / Stop / 弹窗超时把队列标成暂停后，后面每一轮**成功了也不再往下发**，排队的第二条永远停在「待发送」，得手动点「继续队列」——现在任何一轮成功都会清掉暂停标记并立刻发下一条（宿主在缺 Key 的提前返回路径上也补发 `done`，不再让面板以为有任务在飞）。② 定时任务夜里没人守着，写入/命令/工具审批弹窗等满 120 秒被当成拒绝，整条任务白跑——现在定时任务那一轮按推荐选项自动确认，并在对话里留下「[无人值守] 已按推荐自动确认：…」的记录；新增设置 `win7Agent.scheduledUnattended`（默认开）可关掉。
- **v1.12.0**：新增**定时任务**。内网算力白天紧张，可以把跑批排到夜里：输入框写好任务 → 菜单「定时发送…」→ 选 30 分钟后 / 凌晨 02:00 / 自定义 `HH:MM`，并可选「每天这个时间」或「只跑一次」。到点由扩展宿主自己发起一整轮（历史里那条消息带 `⏰ 02:00 定时` 角标），正在回复时排队等这一轮结束；`Ctrl+Shift+P` →「定时任务：管理」可立即执行、暂停、删除。任务存 globalState，重载不丢；计时器只有一个，分段重排以抵抗系统休眠/改时钟。限制写进 README：VS Code 关着不会执行，错过的直接跳过（不补跑）。
- **v1.11.18**：修「任务超时后排队消息卡住」。以前任何一轮出错都会把暂存队列置为「已暂停」，得手动点「继续队列」；可超时（模型服务慢、GGUF 刚加载、内网抖动）跟队列里下一条任务没关系，下一条往往很短就能跑通。现在宿主把失败分类随错误一起发给面板（`src/failure.js`）：超时 → 队列继续，并在对话里留一行「上一轮请求超时，队列继续发送剩余 N 条」；连续 2 条超时才暂停（多半是服务真的挂了），认证失败 / 地址写错 / 弹窗没人点 / 手动 Stop 仍然暂停。一键「继续队列」会重置这个计数。
- **v1.11.17**：修「@ 引用只列出一部分文件」。清单以前来自 VS Code 的 `findFiles`：上限只有 300 个、会被 `files.exclude`/`search.exclude` 过滤，而且刚打开窗口、搜索索引还没就绪时首次查询会返回空或残缺——这正是「首次载入打 @ 很多文件找不到」的原因。现在扩展自己按广度优先遍历工作区（`workspace.fs`），只跳过 `node_modules`/`.git` 这类目录，上限 4000 个文件、深度 12、6 秒超时；面板一出现就在后台预热索引，第一次打 @ 不用等；清单为空或读取失败会在弹层里说明原因，并提供「重新读取工作区文件」。拖拽文件按名匹配也改用同一份清单，命中率一并提高。
